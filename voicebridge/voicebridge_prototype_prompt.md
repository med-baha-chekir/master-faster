# VoiceBridge — Flutter Prototype Prompt

## App overview

Build a Flutter mobile app called **VoiceBridge**. VoiceBridge is an AI-powered voice agent app that lets non-verbal users and people with speech anxiety make phone calls completely hands-free. Instead of the user speaking, an AI agent places the call and speaks on their behalf. The user communicates entirely through tappable response cards on screen in real time.

The app targets users who are non-verbal due to ALS, autism, selective mutism, cerebral palsy, laryngectomy, or severe social anxiety, as well as elderly users who find phone calls overwhelming. It must run on any Android or iOS smartphone with no special hardware.

---

## Prototype scope

This is a functional prototype. Use mock/simulated data where real APIs are not yet connected. All screens must be navigable. Core flows must feel real even if backed by fake responses.

## Screens to build

### 1. Onboarding / profile setup
- Collect: full name, home address, optional secondary delivery address, date of birth, preferred language (Arabic / French / English), emergency contact name + phone number, optional medical/disability note (free text, e.g. "non-verbal due to ALS")
- Collect AI voice preference: male / female / neutral
- Collect speaking style preference: formal / casual
- Store everything in Firebase Firestore under the authenticated user's document
- Show a progress indicator across the setup steps
- Skip button available (fills with defaults, can edit later in Settings)

### 2. Home / scenario selection screen
- Clean card grid showing pre-built call scenarios:
  - Order food from a restaurant
  - Request home delivery
  - Ask for information (hours, prices, availability)
  - Book an appointment (doctor, salon, service)
  - Report a problem (utility issue, complaint)
  - Contact customer support
  - Emergency (SOS — separate prominent red button)
- A free-text field at the bottom: "Describe a custom scenario..." with a keyboard icon
- Each scenario card shows an icon and a short label
- Tapping a scenario navigates to the Call Setup screen
- The SOS button skips directly to an emergency call flow

### 3. Call setup screen
- Shows the selected scenario name and icon at the top
- Phone number input field (E.164 format, with country code picker defaulting to +216 Tunisia)
- A "Saved contacts" button that opens the device contact picker (use `flutter_contacts` package)
- A "Start call" prominent button at the bottom
- Brief scenario summary shown below the number field: what the AI will say to open the call

### 4. Live call screen (the core screen)
- Status bar at the top: call timer, mute button (mutes the AI — pauses it), end call button
- Live transcription panel (top half): scrollable text showing what the other party is saying, in large font (min 18sp), high contrast
- Response card panel (bottom half): 2–4 large tappable cards that appear dynamically based on what the other party just said. Each card is a full-width rounded button with a short plain-language label (e.g. "Delivery", "Pickup", "Yes", "No", "Repeat that please")
- When the user taps a card, it highlights briefly, then the AI speaks the full sentence
- A "Type custom reply" button opens a text field for free-form input
- If the AI is speaking, show an animated waveform or pulsing indicator
- If on hold / waiting, show a neutral "waiting..." state

### 5. Post-call summary screen
- Card showing: call duration, phone number called, scenario used
- Summary text: plain language description of what was agreed/confirmed (e.g. "Food order placed. Estimated delivery in 35 minutes to your home address.")
- List of follow-up actions if any
- Two buttons: "Save to history" and "Done"
- This summary is generated by the Claude API from the full call transcript

### 6. Emergency (SOS) flow
- Accessed from the red SOS button on the home screen
- Fullscreen red layout with a single large "Call Emergency Services" button
- Below it: three large icon buttons to select emergency type — Medical, Fire, Danger
- On tap: immediately initiates a call to the local emergency number (197 in Tunisia)
- AI states: user's name, home address (from profile), and selected emergency type
- No scenario menu, no tap cards — the AI handles the entire call autonomously

### 7. Call history screen
- List of past calls, newest first
- Each row: date/time, scenario icon, phone number, call duration, short summary excerpt
- Tap any row to see the full post-call summary

### 8. Settings screen
- Edit profile fields (all fields from onboarding)
- Change AI voice and speaking style
- Change preferred language
- Toggle: "Always show custom reply option" during calls
- App version, about, and privacy policy links

## Accessibility requirements

- Minimum font size: 18sp across the entire app
- All tap targets minimum 56x56dp
- High contrast mode support (detect system setting)
- Full screen reader support (semantic labels on all widgets)
- No swipe gestures required during a live call — everything is a single tap
- Support right-to-left layout for Arabic

## AI agent behavior (simulate in prototype)

For the prototype, the live call screen can be driven by a mock script instead of a real phone call. Simulate the following flow to demonstrate the UX:

1. AI opens: "Hello, my name is Sarra and I am an AI assistant calling on behalf of a non-verbal person named [user name]. They would like to [scenario]. Is that okay?"
2. Other party: "Yes, of course. What would they like?" → show cards: "Place a food order" / "Ask about the menu" / "Check delivery times"
3. User taps "Place a food order" → AI speaks it
4. Other party: "Will that be pickup or delivery?" → show cards: "Pickup" / "Delivery"
5. User taps "Delivery" → AI speaks: "He would like it delivered, please."
6. Other party: "What is the delivery address?" → show cards: "[Home address from profile]" / "Different address"
7. Continue for 2–3 more exchanges, then end call
8. Show post-call summary screen with simulated summary text

## Simulated API calls (prototype stubs)

Create a `services/` directory with the following stub classes. Each has a `// TODO: replace with real API` comment and returns mock data for now:

- `VapiService` — `startCall(scenario, phoneNumber)`, `endCall()`, `sendUserChoice(cardText)`
- `TranscriptionService` — `streamTranscript()` returns a Stream of fake transcript lines on a timer
- `LLMService` — `generateResponseCards(transcript)` returns a Future of 2–4 mock card labels, `generateCallSummary(fullTranscript)` returns a mock summary string
- `TTSService` — `speak(text)` plays a local beep or uses Flutter TTS package as a stand-in
- `TelephonyService` — `placeCall(e164Number, callerIdNumber)`, `hangUp()`

## Design guidelines

- Primary color: deep purple `#534AB7`
- Accent color: teal `#1D9E75`
- Emergency color: `#E24B4A`
- Background: white / near-white `#F8F8F8`
- All cards use 16dp border radius
- Bottom sheet pattern for any overlays during a live call (never full navigation push)
- Use Material 3 (`useMaterial3: true`)
- The live call screen must feel calm and readable — no animations that could distract or cause anxiety
